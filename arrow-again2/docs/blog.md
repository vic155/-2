## 2. 项目介绍

游戏的目标是按照合适的顺序，清除棋盘上的全部箭头。每个箭头只占据一个格子，方向分为上、下、左、右。点击箭头时，如果它与前进方向的棋盘边界之间没有其他箭头，就允许飞出；只要路径上存在任意方向的其他箭头，就判定受阻。

每关有 3 次失误机会。点击受阻箭头扣除一次机会；空白格或棋盘外的点击不扣次数。清空当前关卡后显示通关结果，可以进入下一关；失误机会耗尽后显示失败结果，可以重试。重新开始会同时恢复布局、剩余数量和失误机会。

项目提供 3 个关卡：第一关“初见方向”为 5×5、12 支箭头；第二关“回旋小径”为 6×6、22 支箭头；第三关“层层解围”为 7×7、33 支箭头。三个关卡对应三档难度，每次开始都会随机生成可解布局；重开恢复本题，换题生成同难度新题。除基础要求外，还提供关卡选择、计时和提示功能：提示会寻找当前可以直接飞出的箭头，帮助玩家理解阻挡关系；结果页显示移出数量、用时和提示次数。

操作方式为鼠标点击，`R` 重开本题，`N` 换题，`H` 提示，`M` 开关音效，`Esc` 返回开始界面。按钮、消除、碰撞、通关与失败各有短音效。

## 3. 实现思路

### 3.1 分离游戏规则与图形界面

项目按职责拆分：`main.py` 启动程序，`arrow_game/app.py` 处理绘制、鼠标键盘输入和动画，`arrow_game/model.py` 处理方向、路径判断及状态变化，`arrow_game/levels.py` 定义难度与生成随机题，`arrow_game/audio.py` 管理音效和静音。

这样做的好处是：路径检测不需要打开游戏窗口就可以测试；修改颜色、按钮或动画时，不必改动规则代码。界面根据逻辑层返回的结果决定播放飞出或碰撞反馈。

### 3.2 箭头、方向与关卡的表示

棋盘坐标采用 `(行, 列)`，左上角为 `(0, 0)`。行号向下增加，列号向右增加。当前仍存在的箭头保存在字典中：

```python
# 表示方式示意，具体类型见 arrow_game/model.py
board[(row, col)] = direction
```

四个方向分别对应一个移动增量：

| 方向 | 标记 | 行增量 dr | 列增量 dc |
| --- | --- | --- | --- |
| 上 | U | -1 | 0 |
| 下 | D | 1 | 0 |
| 左 | L | 0 | -1 |
| 右 | R | 0 | 1 |

关卡中的 `U/D/L/R` 表示箭头，`.` 表示空格。游戏开始时把关卡数据转换成位置与方向的映射。删除箭头只改变当前棋盘，关卡的原始定义保留，因此重新开始可以重新构建初始状态。

### 3.3 路径检测

检测从箭头的下一格开始，按方向增量逐格移动，直到走出棋盘。如果遇到一个仍存在的箭头，立即返回这个阻挡位置；如果扫描完都没有阻挡，则允许消除。

下面是核心算法的简化示意，变量命名为便于说明作了精简：

```python
def first_blocker(board, row, col, dr, dc, rows, cols):
    row += dr
    col += dc
    while 0 <= row < rows and 0 <= col < cols:
        if (row, col) in board:
            return (row, col)
        row += dr
        col += dc
    return None
```

例如同一行中的 `→ · · ↑ ·`，最左侧箭头向右扫描时会遇到向上的箭头，因此不能飞出。阻挡判断只依赖位置，不依赖阻挡箭头的方向。位于边缘且朝外的箭头，其下一格已经越界，循环不会执行，自然得到无阻挡结果。

一次检测最多扫描一行或一列，时间复杂度为 `O(max(行数, 列数))`，额外空间为 `O(1)`。本项目棋盘很小，逐格检测直观且足够高效。

### 3.4 输入、动画与状态

正常游戏状态下才允许点击棋盘。无阻挡时移除对应箭头，并绘制独立的飞出动画；有阻挡时不修改布局，只扣减失误机会并显示碰撞反馈。播放动画时锁定新的棋盘操作，避免快速连续点击造成重复扣次数或状态不同步。

当剩余箭头为零时进入通关状态；当失误机会为零时进入失败状态。结果界面提供后续操作，最后一关完成后显示“最后一关，挑战成功！”，不继续访问不存在的关卡。由于主页允许直接选择第三关，程序只说明最后一关已完成，不据此推断玩家此前已通过另外两关。

### 3.5 关卡可解性与提示

程序可以反复寻找一个当前没有阻挡的箭头并移除，得到一个通关顺序。该方法适用于本作业的基础规则：消除一个箭头只会减少其他箭头前方的阻挡，不会增加新的阻挡。因此，先消除当前可消除的任意箭头不会破坏可解性。

如果棋盘未清空，却已没有任何可消除的箭头，说明剩余布局存在死锁。第二版先构造合法的剥离顺序来生成箭头方向，再以独立求解器验证 300 道随机题。生成算法随机选格子，每步为当前能向外离开的格子指定方向并移除，最后保留所有指定方向作为完整题目；按同一剥离顺序即可通关。每个非空集合总有边缘极端格子，所以算法不会因随机死锁而停滞。详见 [可解性说明](solutions.md)。提示功能利用同样的路径检测，选择当前可消除的箭头。

## 5. 测试过程与结果

### 5.1 测试环境与方法

- 环境：Windows 64 位，Python 3.12.7，pygame-ce 2.5.7。
- 自动测试命令：`python -m unittest discover -s tests -v`。
- 执行并保存检查记录：`python tools/run_checks.py`。
- 界面演示采集：`python tools/capture_demo.py`。
- 本人手工测试：按 [本人试玩记录表](manual-playtest.md) 实际操作并记录，不能只观看演示 GIF。

当前版本 **56 项测试全部通过**，包括 29 项逻辑、23 项界面和 4 项音频测试。新增主页箭头互动、入场时点击立即响应和入场不计时检查。其中随机题检查使用每档 100 个种子，共 300 道题，每题都经独立求解器求解并逐步点击回放，最终通关且没有失误。还覆盖相同种子的复现、重开保留原题、换题重置状态、静音、音频设备不可用与动画期间连点等情况。实际时间及原始输出见 [test-results.txt](test-results.txt)。

第二版使用实际 `GameApp` 渲染器与事件队列重新回放三个难度、失败、重开、换题和静音。截图与 GIF 为程序实际渲染，固定种子只用于演示复现；正常游玩仍随机。报告见 [render-check.json](render-check.json)。GIF 本身不包含音频。

Windows exe 已随第二版重建，原生启动检查覆盖资源加载、菜单、随机题、有效点击、重开及音效开关。实际结果见 [package-check.json](package-check.json)。可用 `ArrowAgain.exe --smoke-test` 复现，源码也支持相同参数。自动检查不代替本人试玩或试听。

音频测试还发现：关闭 mixer 后调用旧 Sound 对象可能使底层库直接退出进程。修复方法是在播放与静音操作前先检查 `pygame.mixer.get_init()`，关闭时不再调用声音对象。对应回归测试已通过。

第一版的视觉复查还发现了自动流程测试未覆盖的问题：末关标题新增“功”字，但旧版字体子集没有收录，导致缺字。代理重新提取界面所需字形，重新生成字体、截图和 exe，并增加中文字符串字形覆盖的回归测试。测试除了判断字形信息不为 `None`，还要求字形边界框的宽和高都大于 0，因为 SDL 对缺字可能返回带正常前进宽度的空白字形。修复后的 37 项测试通过。这说明程序可以正常运行与界面内容完整是两项不同的验证目标。
