# 关键代码理解与答辩说明

这份说明帮助提交者阅读代码。建议打开对应源码，自己逐行追踪一次点击，不要只背结论。

## 1. 先读哪些文件

1. `arrow_game/levels.py`：看一关如何用方向字符与空格定义。
2. `arrow_game/model.py`：理解坐标、方向、阻挡检测、点击结果和重开。
3. `arrow_game/app.py`：理解鼠标位置如何对应格子，以及动画如何显示逻辑结果。
4. `tests`：看边缘、碰撞、失败、重开和可解性分别怎样验证。
5. `main.py`：确认启动入口如何创建并运行游戏。

## 2. 一次点击发生了什么

先判断当前是否允许游戏输入，再把鼠标坐标转换为行列。格子里没有箭头时直接忽略；有箭头时读取其方向，从下一格开始扫描。遇到其他箭头便受阻，保留布局、扣一次失误并播放碰撞反馈；扫描到边界仍没有阻挡则消除箭头，播放飞出动画。之后根据剩余箭头与失误机会决定继续、通关或失败。

动画期间暂时锁定棋盘点击。这是为了防止玩家在同一次视觉反馈结束前再次触发状态变化，导致数量、动画和结果界面不同步。

## 3. 常见问题

### 为什么用 `(行, 列)`，而绘制时又用 `(x, y)`？

行列适合描述二维棋盘。屏幕的 `x` 对应列，`y` 对应行，因此从棋盘位置转到屏幕时，横坐标由列计算，纵坐标由行计算。把二者混用会使上、下与左、右判断错位。

### 为什么从箭头的下一格开始检测？

当前格子存放的是被点击箭头本身。从本格开始会把它误判成自己的阻挡者。先加一次方向增量，再进入边界内循环，就只检查前方格子。

### 只检查紧邻格子可以吗？

不可以。箭头需要一直飞到棋盘外。即使相邻格为空，更远处的箭头仍会阻挡，例如 `→ · · ↑ ·`。必须扫描到边界或遇到第一个阻挡者。

### 阻挡箭头朝向不同，是否仍然阻挡？

仍然阻挡。基础规则只看前方格子是否被占用，不区分阻挡者方向。方向决定的是被点击箭头的扫描方向。

### 边缘朝外的箭头为什么不会数组越界？

扫描先计算下一格，然后判断它是否处于合法行列范围。边缘朝外时下一格已经越界，循环不会进入，也不会读取越界格子，因此得到无阻挡结果。

### 发生碰撞时应该删除箭头吗？

不应该。碰撞只减少失误机会并播放反馈，棋盘占用保持不变。否则玩家可以用碰撞绕过解谜规则，还会让显示数量与规则冲突。

### 重新开始如何保证恢复初始布局？

关卡定义与当前游戏棋盘分开存储。新游戏及重开时，从关卡定义重新构建当前棋盘，并重置失误、状态和界面动画。不能把已经删除部分箭头的当前棋盘直接当成初始数据。

### 清空最后一关后还会进入下一关吗？

不会。只有存在下一关时才允许切换。最后一关显示“最后一关，挑战成功！”，提供重试或回到主页等操作。主页允许直接选择第三关，因此最后一关通关并不能证明前两关也已完成，结果文案需要与实际状态一致。

### 为什么逐个删除可消除箭头就能验证关卡？

在本题规则下，移除箭头只会降低占用，不会添加阻挡。原来可以消除的箭头，不会因其他箭头先被删除而变成不可消除。所以找到当前任意可消除箭头就可以安全推进。若尚有箭头却找不到可消除项，剩余棋盘已经死锁。

### 提示会“作弊”改变棋盘吗？

提示使用相同的路径检测，找出一个当前可直接飞出的箭头并在界面标出。它帮助观察方向关系，不需要修改布局或消除箭头。

### 为什么把规则与界面拆开？

规则不依赖窗口、鼠标或字体，因此可以用普通单元测试验证。界面只负责输入与反馈。两者分离后，改变配色不会影响路径算法，也更容易定位错误来自规则还是绘制。

### 自动测试通过是否就代表可以直接提交？

37 项测试全部通过，覆盖规则、主要界面流程和中文字体覆盖；更新字体后的 Windows exe 启动检查也已通过，验证了打包后的启动与资源加载。它们不代表提交者本人已试玩或理解代码，也不表示代码已经上传 GitHub。仍需完成本人逐关试玩、填写博客、上传仓库并按课程要求提交。

### 为什么从其他目录启动 exe 也能找到字体？

资源路径根据源码所在位置或 PyInstaller 解包目录确定，不依赖终端当前目录。`tools/build_exe.py` 使用绝对路径把 `assets` 包入程序；`--smoke-test` 会短暂渲染菜单和棋盘，便于检查打包后的资源是否正常加载。

### 为什么只改一句文案也需要重新生成字体？

项目使用裁剪后的中文字体，只包含生成时收集到的字符。改文案后如果新增汉字，旧字体可能没有相应字形。本次把末关标题改为“挑战成功”时就发现“功”缺失，已通过重建字体子集、重导截图和重新打包修复。新增回归测试检查源码中的中文字符串，要求字形信息不为 `None`，并且边界框的宽和高都大于 0；仅检查 `None` 不够，因为 SDL 对缺字可能返回空白字形。

### 算法复杂度是多少？

单次扫描最多经过一整行或一整列，时间复杂度为 `O(max(行数, 列数))`，额外空间为 `O(1)`。求解器需要多次扫描当前箭头，复杂度更高，但 7×7 以内的棋盘足够小，清晰的实现比提前优化更适合本项目。

## 4. 自己动手验证

- 找一个边缘朝外的箭头，手工写出它的下一格坐标，确认边界条件不成立。
- 找一个被阻挡的箭头，写出扫描经过的所有格子和第一个阻挡位置。
- 清除一次、碰撞一次，然后重新开始，观察数量与失误是否都恢复。
- 按提示完整通过三关，再尝试不使用提示完成一次。
- 在源码中指出处理“失败”和“最后一关完成”的具体条件。
